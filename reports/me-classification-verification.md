## 적용한 변경

- 프론트엔드의 `statusClassificationVerified`, `chargerTypeClassificationVerified`를 분리했습니다. 현재 둘 다 false입니다.
- 명시적인 독립 flag가 있으면 기존 통합 flag보다 우선합니다. 기존 통합 ME flag만 있는 응답은 호환 처리합니다.
- 상태가 단독 검증된 ME 응답을 수신하면 유형 검증과 무관하게 원본 코드를 보존하면서 백엔드의 해석된 상태를 사용하도록 adapter와 상태 KPI 조건을 분리했습니다. 현재 백엔드는 기존 통합 검증 계약을 유지합니다. 문서 없이 백엔드 매핑을 활성화하지 않았습니다.
- 환경공단 API 연결, 실제 원자료 표시, 서울 지도는 코드 검증 및 D1 confirmed=0과 독립적으로 유지합니다.
- 화면에서 운영상태 코드와 급속/완속 코드를 각각 “공식 v1.25 코드표 확인 필요”로 표시합니다.
- 한전 연결·schema·상태 매핑은 위 검증 판단에 사용하지 않습니다. 품질 화면에만 “한전 교차검증: 현재 미사용”으로 표시합니다.
- 운영중지와 물리적 고장을 동일시하지 않습니다. 점검을 자동 복구 후보로 지정하지 않습니다. 원본 stat=4 행은 식별자로 필터링 가능하지만 공식 코드 검증 전 “복구 검토 대상”으로 승인하지 않습니다. D1-D3 confirmed=0도 그대로 유지합니다.

## 검증 결과

모델 테스트 15개와 격리 브라우저 fixture 검증이 통과했습니다. 실제 localhost 브라우저 검증 결과는 `seoul-operations-browser.json`에 있습니다. 원본 코드 집계는 `me-classification-audit.json`에 있습니다.

## 남은 작업

공식 v1.25 파일 확보 후 stat 표와 chgerType 전체 표를 직접 읽고 위 실제 코드 집합과 비교해야 합니다. 문서에 없는 코드는 원본을 보존하며 UNKNOWN/분류보류로 처리합니다. 검증 근거와 함께 상태/유형을 각각 활성화한 뒤, 서울 상태 KPI 및 운영중지 복구 검토 후보 추출을 검증합니다.
