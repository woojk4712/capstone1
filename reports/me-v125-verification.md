# 환경공단 v1.25 공식 코드 적용 결과

공식 원본 `docs/한국환경공단_전기자동차 충전소 정보_OpenAPI활용가이드_v1.25.docx`를 직접 읽었습니다. 원본은 변경하지 않았습니다. 환경공단 운영상태 분류를 활성화했으며 한전은 사용하지 않습니다. API 인증정보·URL·외부 수집 요청 로직·.env는 변경하지 않았습니다.

## 상태 코드

본문 응답 필드 설명에는 0~5만 있지만 부록 충전기 상태 코드표에는 6과 9도 있습니다. 부록을 기준으로 다음을 적용합니다.

| stat | 공식 설명 | 내부 상태 | 화면 의미 |
|---|---|---|---|
| 0 | 알수없음 | UNKNOWN | 알수없음 |
| 1 | 통신이상 | COMM_ERROR | 통신이상 |
| 2 | 충전대기 | AVAILABLE | 충전대기 / 사용가능 |
| 3 | 충전중 | CHARGING | 충전중 |
| 4 | 운영중지 | STOPPED | 운영중지 · 복구 검토 |
| 5 | 점검중 | MAINTENANCE | 점검중 |
| 6 | 예약중 | UNKNOWN | 예약중 · 정상/중지에 합산하지 않음 |
| 9 | 상태미확인 | UNKNOWN | 상태미확인 |
| 표에 없는 코드 | 공식 의미 없음 | UNKNOWN | 상태미확인 · 원본 코드 보존 |

실제 DB의 distinct stat: `1, 2, 3, 4, 5, 9`. 원본 stat과 statUpdDt를 보존합니다. `statusClassificationVerified=true`입니다. 내부 MAINTENANCE는 공식 점검중을 나타내는 기존 내부 enum으로 유지하여 기존 분석 코드를 보존합니다.

## 충전기 유형 코드

부록에는 본문보다 상세한 11번 유형이 포함되어 있습니다.

| chgerType | 공식 설명 | 급속/완속 판단 |
|---|---|---|
| 01 | DC차데모 | 급속 여부 보류 |
| 02 | AC완속 | 완속 |
| 03 | DC차데모+AC3상 | 급속 여부 보류 |
| 04 | DC콤보 | 급속 여부 보류 |
| 05 | DC차데모+DC콤보 | 급속 여부 보류 |
| 06 | DC차데모+AC3상+DC콤보 | 급속 여부 보류 |
| 07 | AC3상 | 급속 여부 보류 |
| 08 | DC콤보(완속) | 완속 |
| 09 | NACS | 급속 여부 보류 |
| 10 | DC콤보+NACS | 급속 여부 보류 |
| 11 | DC콤보2(버스전용) | 급속 여부 보류 |

실제 DB의 distinct chgerType: `01, 02, 03, 04, 05, 06, 07, 08, 10, 11`. 모든 관측된 커넥터 유형을 공식 표에서 확인했습니다. 다만 표는 커넥터 설명이며 02·08 외에는 급속/완속을 명시하지 않습니다. 11을 미등록 코드로 취급하지는 않지만 커넥터 명칭이나 출력값만으로 급속이라고 확정하지 않습니다.

`FAST_TYPES=[]`, `SLOW_TYPES=[02,08]`, 나머지는 급속 여부 보류입니다. 따라서 `chargerTypeClassificationVerified=false`를 유지합니다. 급속 여부를 명시한 환경공단 공식 근거가 확보되면 이 부분만 추가 검증하면 됩니다. 유형 검증 보류는 상태 KPI와 지도 표시를 막지 않습니다.

## 실제 저장 관측 집계

서울특별시 주소, delYn=N, 유효 좌표 조건: 충전기 70,121기 / statId 충전소 12,146개입니다. 완속을 포함한 원자료 범위입니다.

| 상태 | 마지막 저장 관측 건수 |
|---|---:|
| 사용가능 / 충전대기 | 51,463 |
| 충전중 | 14,793 |
| 운영중지 | 67 |
| 점검중 | 287 |
| 통신이상 | 719 |
| 상태미확인 | 2,792 |

운영중지 67기의 statId/chgerId는 모두 존재하고 복구 검토 후보로 추출 가능합니다. 점검중 287기는 복구 검토 후보에서 제외합니다. 운영중지를 물리적 고장 확정으로 해석하지 않으며 고장원인·수리난이도·복구시간·부품을 생성하지 않습니다. D1-D3 confirmed는 0이므로 기존 핵심 분석시설 우선순위는 매칭 대기 상태입니다.

위 숫자는 마지막 저장 관측의 코드 해석 결과입니다. 검증 시 실행 서버는 수집 진행 중이며 `stale=true`였습니다. 현재 API는 오래된 상태를 UNKNOWN 처리하고 복구 검토 승인을 보류합니다. 화면에는 관측 유효기간 초과를 별도로 표시하며 최신 수집이 끝나기 전 상태 KPI를 현재 상태로 주장하지 않습니다. 원자료 지도를 숨기지는 않습니다.

## 적용 및 검증

공식 파일 SHA-256과 검토 계약을 `docs/me_v125_classification.json`에 기록했습니다. 시작 시 원본 해시가 일치할 때만 검토된 상태 매핑을 읽습니다. 한전 연결·schema·코드표는 참조하지 않습니다. 기존 통합 flag는 분석 호환성을 위해 보존하고 상태·유형 독립 flag를 API에 추가했습니다.

- Python 기존 114개 + 공식 코드 검증 3개: 117개 통과
- 프론트 모델 15개 통과
- 격리 브라우저 회귀 검증 통과
- 실제 저장 데이터 읽기 전용 검증 서버에서 상태 검증 완료 문구와 서울 마커/필터/검색/상세 확인
- 사용자 재시작 이후 8000번 `/api/system/status` HTTP 200, 상태 검증 true / 유형 검증 false 확인
- 원본 집계 및 복구 후보 식별자 검증: `reports/me-v125-applied.json`
- 실제 브라우저 최종 결과: `reports/seoul-operations-browser.json`
