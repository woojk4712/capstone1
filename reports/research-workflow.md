## 매칭과 개별 설비 확인

D1 → OA-21712 → 환경공단으로 연결합니다. 원본 이름·주소·ID는 보존하고 별도 정규화 값을 만듭니다. 시설대장은 이름과 전체 주소로 그룹화하며 도로명·건물번호 핵심주소를 별도로 비교합니다. 이름 정확 일치, 독립 주소 일치, D3 statId 유일성, 여러 공식 물리주소 및 설비 ID 충돌 여부를 함께 검사합니다. 이름만 비슷한 후보는 자동 확정하지 않습니다.

자동/수동 확정과 근거는 station_match 및 match_evidence에 저장됩니다. 같은 D1 또는 D3에 여러 확정 링크가 생기지 않도록 유일성 제약을 유지합니다. 데이터 품질에서 사용자가 동일 시설을 직접 확인하고 독립 근거를 작성하면 확정하거나 보류할 수 있습니다. 수동 보류는 일괄 전처리 후에도 유지됩니다. 변경 결과는 API 조회에 즉시 반영됩니다.

급속 설비는 공식 시설대장의 ID와 급속 명시·용량을 실제 D3 설비와 교차 확인합니다. 자료에는 급속 명시 359행, 완속 73행, 타입/용량 표기 충돌 1행이 있습니다. AC3상을 완속으로 기재한 행도 있으므로 커넥터 이름만으로 전국 급속 분류를 확대하지 않았습니다. ID·출력·유형을 확인하지 못한 시설은 분석 보류합니다. 혼합시설은 D2에서 유형 분리가 불가능하므로 HOLD_MIXED로 정비 추천을 보류합니다.

## 알고리즘

### 복구 검토와 잠재 영향

D는 유효 핵심시설 집단의 연간 실제 급속 kWh 평균순위를 `(평균순위-1)/(시설수-1)`로 변환합니다. 동률은 평균순위이며 집단이 하나면 중립값 0.5를 사용합니다. Q는 해당 충전기 출력/P, B는 P/(P+A)입니다. P는 확인된 분석대상 급속 설비의 정격출력 합계입니다.

A는 같은 statId를 제외한 500m/1km의 삭제되지 않은, 정상 상태(2/3), 이용제한 없음, 급속 확인 설비의 정격출력입니다. 이용제한·미확인 유형은 별도 건수로 표시합니다. 다른 구나 서울 경계 밖이라는 이유로 주변망에서 제외하지 않습니다.

주변 유형 미확인 설비가 존재하면 확인된 출력만으로 계산한 B/Impact는 상한입니다. 이 경우 정확한 Final 복구순위에서는 제외하고 잠재 영향 검토에 “상한 · 검토용”으로 표시합니다. 상한 순위를 정확한 실제 고장 영향 순위로 주장하지 않습니다.

기본 동일가중, 수요/출력/대체망 강조 가중치를 지원합니다. 순서는 Impact 내림차순, 출력 내림차순, statId, chgerId입니다. 실제 복구 검토는 stat=4만 사용하며 점검·통신이상·상태미확인은 물리적 고장으로 취급하지 않습니다. 잠재 영향과 실제 복구순위는 별도 화면입니다.

### 정비시간

D2 원본과 충전량(kW) 표기를 보존합니다. 결측/날짜 파싱/시작>종료/음수·비정상 값/중복 의심 플래그를 남깁니다. 실제 데이터에서 비정상 충전량 1행, 시작>종료 2행을 확인했습니다. 원본 행은 삭제하지 않고 계산에서 유효하지 않은 행만 제외합니다. KST 요일·시·월·반기 파생값도 별도로 보존합니다.

세션이 관측된 날짜만 분모로 사용하고 무기록일을 0건으로 채우지 않습니다. 요일별 정각 1시간/2시간의 평균 시작건수, 시작 시 진행 중 기록 평균, 반기 평균 차이 순으로 정렬합니다. 자정을 넘는 2시간은 양 날짜가 관측된 경우에만 포함합니다. 진행 중 기록은 실제 충전기 대수가 아닙니다. 운영시간을 확인하지 못하면 후보를 보류합니다.

요일×시간 히트맵, 1시간과 2시간 각각의 추천·유효일·시작 시 진행 중 기록·계절 안정성·표본 근거를 표시합니다. 추천은 관측일 기준 계획정비 후보이며 전체 운영일 커버리지를 보장하거나 긴급복구를 미루는 권고가 아닙니다.

### 시뮬레이션과 그래프

실제 복구 시나리오는 유효 stat=4만 선택합니다. 개선 전 정상 가용출력은 상태 2/3 합계이고, 개선 후에는 선택 출력만큼 더하며 운영중지 출력에서는 같은 값을 뺍니다. 회복률은 회복 kW/개선 전 정상 가용 kW×100이며 분모가 0이면 null입니다. 점검 출력은 보존합니다. 기준 잠재 영향 상위 20%의 미복구 수를 비교하며 상한 점수를 포함한 기준은 검토용임을 표시합니다.

실제 운영중지가 없을 때는 가정 시나리오를 별도로 선택할 수 있습니다. 실제 정상 설비를 가상 정지·복구하는 것이며 실제 상태나 DB를 변경하지 않습니다. 과거 관측 재현도 별도의 OFF 기본 옵션입니다. 각 모드에는 실제 결과가 아님을 명시합니다. Preview는 미확정 시설 검토용이며 최종 연구결과와 분리합니다.

누적 회복 그래프는 실제 복구순위, 또는 명시적 가정 시나리오의 선택 설비 순서로 표시합니다. 실제 복구 대상이 없으면 가짜 곡선을 만들지 않습니다. 특정 수리 대수를 권고하거나 미래 이용량·대기시간·수리비·인력·부품을 계산하지 않습니다.

## 실제 검증

- Python 128개, 프론트 모델 15개 통과
- 실제 localhost 브라우저에서 Final 기본값, 500m/1km, 가중치, 잠재 순위 클릭 지도 연동 확인
- D2 히트맵 및 1시간/2시간 개별 추천 확인
- 가정 시나리오 선택, 개선 전/후 지도, 50kW 회복, 누적 회복 SVG 확인
- 일반 탭 진단 배너 숨김, 데이터 품질에서만 진단·자료·매칭 검토 표시 확인
- JavaScript 오류 없음
- 실제 ME DB 읽기 전용 모드에서 시뮬레이션 실행, stat 전후 해시 동일 확인
- 정상출력 증가 = 운영중지 출력 감소 = 회복 kW, 점검출력 불변 검증
- 실제 50kW 가정 복구 사례: 정상출력 18,500→18,550kW, 회복률 0.27027027%

검증 파일: research-browser-verification.json, research-simulation-invariants.json, research-actual-data.json.

## 실행

자료를 교체하거나 추가한 뒤 프로젝트 루트에서 한 번 실행합니다.

```powershell
.\.venv\Scripts\python.exe scripts\prepare_analysis.py --all
```

자료 재계산과 수동 매칭에는 서버 재시작이 필요 없습니다. 이번 코드 버전은 사용자가 일반 Windows PowerShell에서 서버를 재시작하여 반영했습니다. 웹사이트는 http://127.0.0.1:8000/ 에서 Ctrl+F5로 새로고침합니다.
